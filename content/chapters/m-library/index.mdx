The books and courses experienced engineers recommend most often for the ground this course covers, grouped by part. Every link was opened on 13 November 2026. Many are free; the rest are worth buying. You do not need all of them: pick one or two for the part you want to go deeper in, and read them alongside building something (<Ref to="m-projects" />).

## Foundations (parts 1 and 2)

| Resource | Free? | Why read it |
|---|---|---|
| [Computer Systems: A Programmer's Perspective](https://csapp.cs.cmu.edu/), Randal Bryant and David O'Hallaron | No | How programs really run: data representation, machine code, caches, memory, linking, processes. The depth behind <Ref to="m-machine" />. |
| [Operating Systems: Three Easy Pieces](https://pages.cs.wisc.edu/~remzi/OSTEP/), Remzi and Andrea Arpaci-Dusseau | Yes | Processes, scheduling, memory, concurrency and file systems, clearly and with humour. |
| [High Performance Browser Networking](https://hpbn.co/), Ilya Grigorik | Yes | TCP, TLS, HTTP/2 and what latency really costs. |
| [Algorithms](https://jeffe.cs.illinois.edu/teaching/algorithms/), Jeff Erickson | Yes | A rigorous, readable algorithms textbook. |
| [The Algorithm Design Manual](https://www.algorist.com/), Steven Skiena | No | Practical algorithm design, with a catalogue of problems and how to recognise them. |
| [Nand2Tetris](https://www.nand2tetris.org/), Noam Nisan and Shimon Schocken | Yes | Build a computer from logic gates up to an operating system. |
| [Teach Yourself Computer Science](https://teachyourselfcs.com/), Oz Nova and Myles Byrne | Yes | A curated self-study plan through the classic computer science subjects. |
| [The Missing Semester of Your CS Education](https://missing.csail.mit.edu/), MIT | Yes | The shell, editors, Git, debugging and tooling that degrees often skip. |

## Writing excellent code and design (parts 3 and 4)

| Resource | Free? | Why read it |
|---|---|---|
| [A Philosophy of Software Design](https://web.stanford.edu/~ouster/cgi-bin/book.php), John Ousterhout | No | Managing complexity: deep modules, information hiding, and why "tactical" programming hurts. |
| [The Pragmatic Programmer](https://pragprog.com/titles/tpp20/the-pragmatic-programmer-20th-anniversary-edition/), David Thomas and Andrew Hunt | No | The habits of effective engineers, from DRY to tracer bullets. |
| [Refactoring](https://refactoring.com/), Martin Fowler | Catalogue free | The smells and refactorings of <Ref to="m-refactoring" />, in full. |
| [Refactoring Guru: design patterns](https://refactoring.guru/design-patterns), Alexander Shvets | Yes | Every classic pattern with diagrams and code in many languages. |
| [Patterns of Enterprise Application Architecture catalogue](https://martinfowler.com/eaaCatalog/), Martin Fowler | Catalogue free | Repositories, units of work, data mappers and the rest of <Ref to="m-enterprise-patterns" />. |
| [Domain-Driven Design Reference](https://www.domainlanguage.com/ddd/reference/), Eric Evans | Yes | Every DDD pattern in a short reference, from the author. |
| [Building Microservices](https://samnewman.io/books/building_microservices_2nd_edition/), Sam Newman | No | Splitting systems, communication styles and when not to use microservices. |

## Testing, data and distributed systems (parts 5 to 8)

| Resource | Free? | Why read it |
|---|---|---|
| [The Practical Test Pyramid](https://martinfowler.com/articles/practical-test-pyramid.html), Ham Vocke | Yes | A long, practical guide to tests at every level. |

| [The System Design Primer](https://github.com/donnemartin/system-design-primer), Donne Martin | Yes | System design topics and worked examples. |

## How to use the library

- **Read actively**: take notes, try the ideas on real code, and write a short summary of each chapter in your own words.
- **Pair reading with building**: read the chapter on replication while adding a read replica to your project; read about circuit breakers while adding one.
- **Revisit**: the best of these books read differently after a year of experience.
