By the end of this chapter you will be able to build a page out of **components**, small pieces of interface you write once and reuse, and feed them data so the same piece can show a hundred different things. This is how most web applications are built today, and React is the tool most job adverts ask for.

## Why React exists

Think back to the to-do list in <Ref to="js-dom-events" />. Every time something changed, your code had to change the page by hand: create an `li`, add a button, remove an element, recount the summary. The data (the tasks) and the page (the DOM) were two separate things, and your code had to keep them in step. In a small app that is manageable. In an app with hundreds of things on screen, keeping them in step by hand is where most bugs come from.

**React** is a JavaScript library that turns this around. You describe what the page should look like for the data you have now, and React works out which parts of the real page to change. You never write `createElement` or `remove` yourself. If the data changes, you describe the page again, and React makes the smallest set of changes to match.

That way of working is called **declarative**: you declare the result you want. The DOM code you wrote before was **imperative**: step-by-step instructions for how to get there. Both have their place, but for interfaces that change a lot, declarative code is far easier to get right.

React was created at Facebook (now Meta) and is free and open source. This course uses React 19, the current version when this chapter was checked (November 2026).

## Your first React project

React apps are usually made with Vite, which you met in <Ref to="js-modules-tooling" />. Vite has a starter for React:

```bash
npm create vite@latest my-react-app -- --template react
cd my-react-app
npm install
npm run dev
```

The first line creates a folder called `my-react-app` holding a small React project; `--template react` asks for React with plain JavaScript. The other lines go into the folder, install React and Vite, and start the development server. Open the address it prints (usually `http://localhost:5173`) and you will see the starter page. (The `--` passes the template option through `npm` to Vite's starter. If you leave the template out, it asks you questions instead.)

The files that matter:

- `index.html`: an almost empty page containing `<div id="root"></div>` and a `<script type="module">` that loads `src/main.jsx`.
- `src/main.jsx`: finds that `div` and tells React to show the `App` component inside it.
- `src/App.jsx`: the `App` component. **This is where you start writing.**
- `src/App.css` and `src/index.css`: styles.

Here is `src/main.jsx` as the starter creates it:

```jsx
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import './index.css'
import App from './App.jsx'

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <App />
  </StrictMode>,
)
```

Read it as: "Make a React **root** in the element with id `root`, and **render** (show) the `App` component in it." `StrictMode` is a helper that runs extra checks while you develop and shows nothing itself. You will rarely change this file. (The Vite starter leaves out semicolons; the examples in this course use them, as the rest of the course does. JavaScript accepts both.)

The files end in `.jsx` rather than `.js` because they contain JSX, which comes next. Replace everything in `src/App.jsx` with the examples in this chapter to try them in your own project.

Each React example below that is a complete component file has a **Show the result** button. ## Components

A **component** is a JavaScript function that returns a description of some interface. Here is a whole component file:

```jsx
export default function App() {
  return <h1>Hello, React</h1>;
}
```

That is all. `App` is an ordinary function. It returns something that looks like HTML: `<h1>Hello, React</h1>`. `export default` makes it the file's main export, so `main.jsx` can import it (modules and `export default` were in <Ref to="js-modules-tooling" />).

Two rules for components:

1. **The name starts with a capital letter.** React uses this to tell your components (`<App />`) from HTML elements (`<h1>`). A component called `app` would be treated as an unknown HTML tag.
2. **It returns the interface**: some JSX, or `null` to show nothing.

## JSX: HTML-like code inside JavaScript

The HTML-looking code is **JSX**, short for JavaScript XML. It is not HTML and not a string: Vite turns each JSX tag into an ordinary JavaScript function call before your code runs. Roughly:

```text
<h1 className="title">Hello</h1>
        becomes
jsx("h1", { className: "title", children: "Hello" })
```

You will never write those calls yourself, but knowing they exist explains JSX's rules.

### Curly braces: JavaScript inside JSX

Inside JSX, `{ }` means "this part is JavaScript; put its value here". Any expression works: a variable, a sum, a function call, a template literal.

```jsx
const baker = "Ama";
const loaves = 12;
const price = 2.5;

export default function App() {
  return (
    <div>
      <h1>{baker}'s Bakery</h1>
      <p>Today we baked {loaves} loaves.</p>
      <p>All of them would cost £{(loaves * price).toFixed(2)}.</p>
      <p>Opening time: {new Date(2026, 10, 12, 8, 0).toLocaleTimeString("en-GB", { hour: "2-digit", minute: "2-digit" })}</p>
    </div>
  );
}
```

Step by step:

- `{baker}` puts the value of `baker` there: **Ama**.
- `{loaves * price}` is worked out first, 12 × 2.5 = 30, and `.toFixed(2)` turns it into the text `"30.00"`, so the line reads **All of them would cost £30.00.**
- The opening time line calls two functions inside the braces, and shows **08:00**.
- The JSX is wrapped in `( )` because it spans several lines. Without the brackets, a `return` followed by a new line returns nothing; with them, it is clear where the JSX starts and ends.

Braces hold **expressions** (things that produce a value), not **statements** such as `if` or `for`. You will see what to use instead in the sections on conditions and lists.

### JSX rules that differ from HTML

JSX looks like HTML, but a few things are different. Each one trips up every beginner once.

| In HTML | In JSX | Why |
|---|---|---|
| `class="card"` | `className="card"` | `class` is a reserved word in JavaScript |
| `for="email"` on a label | `htmlFor="email"` | `for` is a reserved word too |
| `<img src="a.png">` | `<img src="a.png" />` | every tag must be closed; empty ones close themselves with `/>` |
| `onclick="..."` | `onClick={...}` | event names are in camelCase and take a function, not a string |
| `style="color: red"` | `style={{ color: "red" }}` | `style` takes a JavaScript object; property names are camelCase (`fontSize`) |
| several elements side by side | one wrapping element | a component returns one thing |

The last rule needs an example. A function can only return one value, and JSX becomes a function call, so a component must return one outer element. When you do not want an extra `<div>` in the page, wrap the elements in a **fragment**, written `<>` and `</>`. It groups them without adding anything to the page:

```jsx
export default function App() {
  return (
    <>
      <h1>Ama's Bakery</h1>
      <p>Fresh bread every morning.</p>
      <hr />
      <p>Open every day except Sunday.</p>
    </>
  );
}
```

`<hr />` (a dividing line) closes itself, as every empty element must in JSX. All the good HTML habits from earlier chapters still apply. The `alt` text on images, the `width` and `height`, headings in order, real `<button>`s: React changes how you write the page, not what a good page is.

## Building with components

The point of components is that you combine them. A component can use other components as if they were HTML tags:

```jsx
function Header() {
  return (
    <header>
      <h1>Ama's Bakery</h1>
      <p>Bread, cakes and coffee in Leeds.</p>
    </header>
  );
}

function OpeningHours() {
  return (
    <section>
      <h2>Opening hours</h2>
      <p>Monday to Saturday, 8am to 4pm.</p>
    </section>
  );
}

function Footer() {
  return <footer>© 2026 Ama's Bakery</footer>;
}

export default function App() {
  return (
    <>
      <Header />
      <main>
        <OpeningHours />
      </main>
      <Footer />
    </>
  );
}
```

`App` is now short and reads like a table of contents. Each piece can be read, changed and fixed on its own. The components form a **component tree**: `App` at the top, containing `Header`, `main`, and `Footer`, with `OpeningHours` inside `main`. React shows the page by starting at the top of the tree and working down.

In a real project, each component usually gets its own file (`Header.jsx`, `Footer.jsx`), exported and imported as in <Ref to="js-modules-tooling" />:

```jsx
// Header.jsx
export default function Header() {
  return (
    <header>
      <h1>Ama's Bakery</h1>
    </header>
  );
}
```

```jsx
// App.jsx
import Header from "./Header.jsx";

export default function App() {
  return <Header />;
}
```

The examples on this page keep everything in one file, because the sandbox has only one.

## Props: passing data to a component

A header that always says the same thing is fine, but most pieces should show different data each time: one product card per product. You pass data to a component with **props** (short for properties). They look like HTML attributes:

```jsx
function ProductCard(props) {
  return (
    <article>
      <h2>{props.name}</h2>
      <p>£{props.price.toFixed(2)}</p>
    </article>
  );
}

export default function App() {
  return (
    <>
      <ProductCard name="Sourdough loaf" price={4.5} />
      <ProductCard name="Cinnamon bun" price={2.75} />
      <ProductCard name="Rye loaf" price={3.8} />
    </>
  );
}
```

How it works:

1. `<ProductCard name="Sourdough loaf" price={4.5} />` calls `ProductCard` with one argument, an object: `{ name: "Sourdough loaf", price: 4.5 }`. That object is `props`.
2. Inside, `props.name` is `"Sourdough loaf"` and `props.price` is `4.5`, so the card shows **Sourdough loaf** and **£4.50**.
3. The same component runs three times with three different props, so three different cards appear: £4.50, £2.75 and £3.80.

Notice the two ways of passing a value. Text in quotes (`name="Sourdough loaf"`) passes a string. Anything else goes in braces: `price={4.5}` passes the number 4.5. If you wrote `price="4.5"` you would pass the *text* "4.5", and `props.price.toFixed` would fail, because text has no `toFixed`.

### Destructuring props

Writing `props.` everywhere gets tiring, so most React code unpacks the props straight away with object **destructuring**, which you met in <Ref to="js-arrays-objects" />. These two are the same:

```jsx
function ProductCard(props) {
  const name = props.name;
  const price = props.price;
  return <h2>{name}: £{price.toFixed(2)}</h2>;
}
```

```jsx
function ProductCard({ name, price }) {
  return <h2>{name}: £{price.toFixed(2)}</h2>;
}
```

You can give a prop a **default value**, used when the prop is not passed, in the same way: `function ProductCard({ name, price, currency = "£" })`.

### Props are read-only

A component must never change its props. They belong to the component that passed them in. `props.price = 0` inside `ProductCard` is a bug: React may show stale data, and nothing will warn you. If a component needs a value that changes, that is **state**, the subject of <Ref to="react-state-forms" />.

A helpful way to think about it: a component should behave like a function in maths. The same props in, the same page out. Components that work this way are called **pure**, and React relies on it.

### The children prop

Whatever you put *between* a component's opening and closing tags arrives as a special prop called **children**. It lets you write wrapper components, such as a box with a border, that do not care what is inside them:

```jsx
function Panel({ title, children }) {
  return (
    <section style={{ border: "2px solid #8a5a2b", borderRadius: "8px", padding: "0 16px", marginBottom: "12px" }}>
      <h2>{title}</h2>
      {children}
    </section>
  );
}

export default function App() {
  return (
    <>
      <Panel title="Today's special">
        <p>Pistachio croissant, £3.20.</p>
      </Panel>
      <Panel title="Find us">
        <p>12 Market Street, Leeds.</p>
        <p>Next to the library.</p>
      </Panel>
    </>
  );
}
```

The first `Panel` gets one paragraph as its `children`; the second gets two. `Panel` puts them wherever it writes `{children}`.

## Showing things only sometimes

Often part of the page depends on the data: a "Sold out" label, a message when a list is empty. There are three common ways to write this.

**1. `if` with an early `return`.** Since a component is a function, you can use an ordinary `if` *before* the JSX:

```jsx
function Stock({ count }) {
  if (count === 0) {
    return <p>Sold out</p>;
  }
  return <p>{count} left</p>;
}

export default function App() {
  return (
    <>
      <Stock count={3} />
      <Stock count={0} />
    </>
  );
}
```

This shows **3 left** and then **Sold out**.

**2. The conditional operator `? :`** inside the JSX, for "this or that": `{count === 0 ? <p>Sold out</p> : <p>{count} left</p>}`. It works in braces because it is an expression. It was in <Ref to="js-logic-functions" />.

**3. `&&`**, for "this or nothing": `{isNew && <span>New!</span>}`. If `isNew` is `true`, the result is the `<span>`; if it is `false`, the result is `false`, and React shows nothing for `false`, `null` or `undefined`.

Here are the second and third together:

```jsx
function MenuItem({ name, price, soldOut, isNew }) {
  return (
    <li>
      {name}, £{price.toFixed(2)}
      {isNew && <strong> New!</strong>}
      {soldOut ? <em> (sold out)</em> : <em> (available)</em>}
    </li>
  );
}

export default function App() {
  return (
    <ul>
      <MenuItem name="Sourdough loaf" price={4.5} soldOut={false} isNew={false} />
      <MenuItem name="Pistachio croissant" price={3.2} soldOut={false} isNew={true} />
      <MenuItem name="Rye loaf" price={3.8} soldOut={true} isNew={false} />
    </ul>
  );
}
```

Be careful with `&&` and numbers. React does not show `false`, but it *does* show the number `0`. So `{count && <p>{count} left</p>}` shows a lone **0** when `count` is 0. Write a real true-or-false test instead: `{count > 0 && <p>{count} left</p>}`.

## Lists: one component per item

Real data comes as arrays: a list of products from a server. To turn an array into a list of elements, use the array's `map` method from <Ref to="js-arrays-objects" />. `map` returns a new array, and React shows an array of elements one after another.

```jsx
const products = [
  { id: 1, name: "Sourdough loaf", price: 4.5 },
  { id: 2, name: "Cinnamon bun", price: 2.75 },
  { id: 3, name: "Rye loaf", price: 3.8 },
];

export default function App() {
  return (
    <ul>
      {products.map((product) => (
        <li key={product.id}>
          {product.name}: £{product.price.toFixed(2)}
        </li>
      ))}
    </ul>
  );
}
```

Two things are new here.

**The arrow function returns JSX** using round brackets: `(product) => ( <li>…</li> )`. Round brackets after the arrow mean "return this". If you write curly braces instead, `(product) => { <li>…</li> }`, the function body has no `return`, so it returns `undefined` and the list is empty. This is one of the most common React bugs.

**Every item has a `key`.** A **key** is a value that identifies each item among its siblings, so that when the list changes (an item is added, removed or reordered), React can tell which item is which and update only what changed. Keys must be unique within the list and should stay the same for the same item, so the best key is an id that comes with the data, like `product.id`.

If you leave the key out, the list still appears, but React prints a warning in the developer tools console. Press **Show the result** on this example to see the warning in the messages under it:

```jsx
const names = ["Sourdough loaf", "Cinnamon bun"];

export default function App() {
  return (
    <ul>
      {names.map((name) => (
        <li>{name}</li>
      ))}
    </ul>
  );
}
```

Take the warning seriously. Without keys, React matches items by their position, so after deleting or reordering items it can attach the wrong details to the wrong item (you will see this with form inputs in <Ref to="react-state-forms" />).

What about using the item's position, `map((name, index) => <li key={index}>…)`? It silences the warning but has the same problem whenever the list can change order or lose items, because the positions shift. Use it only for lists that never change. If your data truly has no id, a string that is unique and stable, such as the name in a list where names never repeat, is better than the index.

## A worked example: the bakery menu

Everything so far, in one page. The data is an array of products, as it might come from a server. The page shows each product as a card, marks new items, says when something is sold out, and shows a message instead of an empty section.

<Playground>

```css
.menu {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(180px, 1fr));
  gap: 12px;
  padding: 0;
  list-style: none;
}

.card {
  border: 1px solid #d6c3a5;
  border-radius: 8px;
  padding: 12px;
}

.card h3 {
  margin: 0 0 4px;
}

.sold-out {
  color: #595959;
}

.badge {
  background: #8a5a2b;
  color: white;
  border-radius: 4px;
  padding: 0 6px;
  font-size: 0.8rem;
}
```

```jsx
import "./App.css";

const products = [
  { id: 1, name: "Sourdough loaf", price: 4.5, category: "Bread", stock: 6, isNew: false },
  { id: 2, name: "Rye loaf", price: 3.8, category: "Bread", stock: 0, isNew: false },
  { id: 3, name: "Cinnamon bun", price: 2.75, category: "Cakes", stock: 12, isNew: false },
  { id: 4, name: "Pistachio croissant", price: 3.2, category: "Cakes", stock: 4, isNew: true },
];

function ProductCard({ product }) {
  const soldOut = product.stock === 0;
  return (
    <li className={soldOut ? "card sold-out" : "card"}>
      <h3>
        {product.name} {product.isNew && <span className="badge">New</span>}
      </h3>
      <p>£{product.price.toFixed(2)}</p>
      <p>{soldOut ? "Sold out today" : `${product.stock} left`}</p>
    </li>
  );
}

function MenuSection({ title, items }) {
  return (
    <section>
      <h2>{title}</h2>
      {items.length === 0 ? (
        <p>Nothing in this section today.</p>
      ) : (
        <ul className="menu">
          {items.map((product) => (
            <ProductCard key={product.id} product={product} />
          ))}
        </ul>
      )}
    </section>
  );
}

export default function App() {
  const bread = products.filter((p) => p.category === "Bread");
  const cakes = products.filter((p) => p.category === "Cakes");
  const drinks = products.filter((p) => p.category === "Drinks");
  return (
    <main>
      <h1>Today's menu</h1>
      <MenuSection title="Bread" items={bread} />
      <MenuSection title="Cakes" items={cakes} />
      <MenuSection title="Drinks" items={drinks} />
    </main>
  );
}
```

</Playground>

How it fits together, from the top:

- **`App`** sorts the products into three arrays with `filter`, and passes each to a `MenuSection` along with a title. It does not know how a section or card looks.
- **`MenuSection`** shows a heading, then either a message (when its array is empty, as Drinks is) or a list with one `ProductCard` per product. The `key` goes on `ProductCard`, the element *directly inside* the `map`, not on the `li` inside the card.
- **`ProductCard`** works out `soldOut` from the stock, then uses it twice: to choose the CSS class and to choose the text. The rye loaf has `stock: 0`, so it shows **Sold out today** in grey. The pistachio croissant has `isNew: true`, so it gets a **New** badge.
- **`import "./App.css"`** is how a Vite project adds a CSS file. In the sandbox here, the CSS block above plays that part.
- Passing the whole `product` object as one prop (`product={product}`) is often tidier than passing each field separately.

Try changing the data in the editor: set the cinnamon bun's stock to 0, add a drink, or mark the rye loaf as new. You change only the data, and the page follows. That is the declarative idea from the start of the chapter.

## How React updates the page

You now know enough to see what React does. When `App` runs, it returns a description of the page: a tree of objects saying "an `h1` with this text, then a `section`…". React compares that description with the one from last time and changes only the parts of the real DOM that differ. Producing the description is called **rendering**. Rendering does not touch the page; React updates the page afterwards, in a step called the **commit**.

So far nothing changes after the first render, because nothing in these examples can change. In <Ref to="react-state-forms" />, components get **state**: data that changes when someone clicks or types. When state changes, React renders the component again and updates the page to match.

## Common mistakes

- **Two elements side by side without a wrapper.** Vite stops with `Adjacent JSX elements must be wrapped in an enclosing tag.` Wrap them in a `<div>` or a fragment `<> </>`. (The sandbox on this page reports this one less clearly, as `Unterminated regular expression`.)
- **A tag that is not closed**, such as `<img src="a.png">` or `<br>`. Vite reports something like `Unexpected token. Did you mean {'}'} or &rbrace;?`, which is confusing: the real fix is `<img src="a.png" />`. A closing tag that does not match its opening tag gives `Expected corresponding JSX closing tag for 'p'.`
- **`class` instead of `className`.** It still works in the browser, but React warns: `Invalid DOM property 'class'. Did you mean 'className'?` (React writes the names in backticks).
- **A component name in lowercase.** `function card()` used as `<card />` makes an unknown HTML element called `card` instead of calling your function. Name components with a capital letter.
- **Curly braces after the arrow in `map`**: `items.map((item) => { <li>{item}</li> })` returns nothing, so the list is empty. Use round brackets, or write `return`.
- **A missing `key`**, or a `key` on the wrong element. The key goes on the outermost element inside the `map`.
- **A number in quotes**: `price="4.5"` passes text. Use `price={4.5}`.
- **`{count && …}` showing a 0.** Compare: `{count > 0 && …}`.
- **Changing props** inside a component. Treat props as read-only.
- **Forgetting `export default`** on `App`, so `main.jsx` has nothing to import. `npm run build` stops with `"default" is not exported by "src/App.jsx".`, and the development server shows a similar message in the browser console.

**7. (standard)** Give `Greeting` a second prop, `visits`, with a default value of `1`, and show `This is visit number {visits}.` under the welcome. What does `<Greeting name="Ama" />` show now?

**8. (standard)** This list shows nothing. Why, and what is the fix?

```jsx
const towns = ["Leeds", "York", "Hull"];

export default function App() {
  return (
    <ul>
      {towns.map((town) => {
        <li key={town}>{town}</li>;
      })}
    </ul>
  );
}
```

<Solution>

The arrow function has curly braces, which start a function body, and the body has no `return`, so every call returns `undefined`. Use round brackets, which return the JSX:

```jsx
const towns = ["Leeds", "York", "Hull"];

export default function App() {
  return (
    <ul>
      {towns.map((town) => (
        <li key={town}>{town}</li>
      ))}
    </ul>
  );
}
```

(Or keep the curly braces and write `return <li key={town}>{town}</li>;`.) The town names make fine keys here because they are unique and do not change.

</Solution>

**9. (standard)** A component shows `{basket.length && <p>{basket.length} items in your basket</p>}`. What appears when the basket is empty, and how do you fix it?

<Solution>

A lone **0**. `basket.length` is 0, and `0 && …` gives 0, which React shows (it hides only `false`, `null` and `undefined`). Fix it with a comparison that gives `true` or `false`: `{basket.length > 0 && <p>…</p>}`.

</Solution>

**10. (standard)** Write a `Badge` component that takes `stock` and shows `Sold out` when stock is 0, `Only {stock} left` when it is 1 to 3, and nothing at all otherwise. Show three badges, for stock 0, 2 and 10.

**13. (stretch)** Split this into components: a page with a heading `Our team`, then for each person a card showing their name in an `h2` and their role in a `p`. **14. (stretch)** Show only the products under £3.50 from the worked example's data, sorted from cheapest to dearest, with a line under the list giving how many there are. What does it show?

<Solution>

```jsx
const products = [
  { id: 1, name: "Sourdough loaf", price: 4.5 },
  { id: 2, name: "Rye loaf", price: 3.8 },
  { id: 3, name: "Cinnamon bun", price: 2.75 },
  { id: 4, name: "Pistachio croissant", price: 3.2 },
];

export default function App() {
  const cheap = products
    .filter((p) => p.price < 3.5)
    .sort((a, b) => a.price - b.price);
  return (
    <>
      <ul>
        {cheap.map((p) => (
          <li key={p.id}>
            {p.name}: £{p.price.toFixed(2)}
          </li>
        ))}
      </ul>
      <p>{cheap.length} items under £3.50</p>
    </>
  );
}
```

It shows **Cinnamon bun: £2.75**, then **Pistachio croissant: £3.20**, then **2 items under £3.50**. The filtering and sorting happen in ordinary JavaScript before the JSX; the JSX only shows the result. (`filter` makes a new array, so `sort`, which changes the array it is called on, does not change `products`.)

</Solution>

**15. (stretch)** Explain in your own words why `key={index}` causes problems when an item is deleted from the middle of a list, using a list of three names as the example.

<Solution>

Take `["Ama", "Kofi", "Priya"]` with keys 0, 1 and 2. Delete Kofi, and the list becomes `["Ama", "Priya"]` with keys 0 and 1. React compares keys: key 0 is still there (Ama, unchanged), key 1 is still there but its name changed from Kofi to Priya, and key 2 has gone. So React thinks *Priya's* item was deleted and *Kofi's* item was renamed. With plain text the page still looks right, but anything else React keeps for each item (what was typed into an input in it, whether it was open, its animation) stays with the old position and ends up beside the wrong name. With `key={person.id}`, the keys follow the people and React removes the right one.

</Solution>

## Summary

- **React** lets you describe what the page should look like for your data; it updates the real page to match. That style is **declarative**.
- A **component** is a function, named with a capital letter, that returns **JSX**. Components combine into a tree, with `App` at the top.
- JSX is not HTML: `className`, `htmlFor`, closed tags (`<img />`), camelCase events, `style` as an object, and one outer element (use a **fragment**, `<> </>`, when you do not want a wrapper).
- `{ }` in JSX holds a JavaScript expression: a variable, a sum, a function call, `? :`, `&&`.
- **Props** pass data into a component. They arrive as one object, usually destructured: `function Card({ name, price })`. Strings in quotes, everything else in braces. Props are read-only.
- **children** is what you put between a component's tags.
- Show things conditionally with an early `return`, `? :` or `&&` (watch out for `0 &&`).
- Show arrays with `map`, round brackets after the arrow, and a unique, stable **key** on each item: an id from the data, not the index.
