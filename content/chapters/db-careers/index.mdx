By the end of this chapter you will know the main jobs where database skills are central, what each does day to day, which parts of this course matter most for each, and how to show employers you can do the work. SQL is one of the most consistently requested skills in technology job adverts, across engineering, data and analytics roles.

## The roles

| Role | Day to day | Most important chapters |
|---|---|---|
| **Back-end engineer** | designs tables and migrations, writes queries and ORM code, makes services fast and correct | modelling, indexes, query plans, transactions, migrations, databases from code |
| **Database administrator (DBA)** or **database reliability engineer** | runs databases: backups, replication, upgrades, tuning, security, incident response | operations, security, performance, migrations, transactions |
| **Data engineer** | builds pipelines that move and transform data between systems and into warehouses | analytics, performance, modelling, plus a programming language and orchestration |
| **Analytics engineer** | models data in the warehouse for reporting, with tested, version-controlled SQL (often dbt) | analytics, window functions, advanced queries, modelling |
| **Data analyst** | answers business questions with SQL and dashboards, and explains the findings | SQL from zero, advanced SQL, analytics |

Titles vary between companies; read what the job actually involves. Many people move between these roles: analysts become analytics engineers, back-end engineers specialise in databases, DBAs become platform or reliability engineers.

## What employers look for

- **Strong SQL**, tested in interviews (<Ref to="db-interview-sql" />), for every role.
- **Data modelling**: designing schemas that answer the business's questions and keep data correct.
- **Performance**: reading plans, choosing indexes, explaining why a query is slow.
- For engineering and DBA roles: **transactions and concurrency**, **operations** (backups, replication, monitoring) and **cloud** managed databases.
- For data roles: **warehouses** (BigQuery, Snowflake, Redshift, Databricks), **dbt**, a **programming language** (usually Python) and **orchestration** (Airflow, Dagster).
- Communication: explaining data to people who do not read SQL.

## Getting there

1. **Finish the projects** in <Ref to="db-projects" /> that match the role you want, and publish them with clear `README`s.
2. **Practise interview SQL** until the common patterns are automatic.
3. **Learn the tools the adverts name**: a specific cloud's managed database or warehouse, dbt, Airflow.
4. **Consider a certification** only where your target employers value it (cloud database certifications from AWS, Microsoft or Google; vendor certifications for Oracle or SQL Server roles). Projects usually count for more.
5. **Contribute and write**: answer questions on community forums, write up a performance investigation, or contribute to an open-source tool; it shows depth and communication.
6. For general job-search advice (CVs, applications, interviews), see <Ref to="career" />.

## Summary

- Database skills are central to **back-end engineers**, **DBAs and database reliability engineers**, **data engineers**, **analytics engineers** and **data analysts**.
- All need strong SQL; engineers and DBAs add transactions, operations and performance; data roles add warehouses, dbt, Python and orchestration.
- Build and publish projects for the role you want, practise interview SQL, and learn the tools the adverts name.
