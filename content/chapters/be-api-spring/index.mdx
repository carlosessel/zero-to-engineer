By the end of this chapter you will build a JSON API with **Spring Boot**, the most used Java framework for back ends: controllers with routes and parameters, request bodies bound to records, Bean Validation, consistent errors as problem details, services injected into controllers, configuration, and an OpenAPI description. This is the Java track's API chapter; <Ref to="m-api-design" /> covers what makes an API well designed, and <Ref to="be-http" /> the HTTP underneath.

## Spring and Spring Boot

**Spring** is a large framework for Java applications, whose core is a **container** that creates your objects and wires them together (<Ref to="be-dependency-injection" />). **Spring Boot** sits on top and makes it quick to start: it picks sensible defaults, configures what it finds on the classpath (add the web starter and you get an embedded Tomcat web server, JSON with Jackson, and error handling), and packages everything into one runnable `.jar`.

Start a project at **Spring Initializr** (start.spring.io, or the "New project" wizard in IntelliJ IDEA or VS Code): choose Gradle or Maven, Java 21 or later, and the dependencies Spring Web and Validation. You get a build file like this (Gradle, Kotlin DSL):

```kotlin
plugins {
    java
    id("org.springframework.boot") version "4.1.2"
    id("io.spring.dependency-management") version "1.1.7"
}

group = "com.bakery"
version = "0.0.1-SNAPSHOT"

java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(21)
    }
}

repositories {
    mavenCentral()
}

dependencies {
    implementation("org.springframework.boot:spring-boot-starter-webmvc")
    implementation("org.springframework.boot:spring-boot-starter-validation")
    implementation("org.springdoc:springdoc-openapi-starter-webmvc-api:3.2.0")
    testImplementation("org.springframework.boot:spring-boot-starter-test")
    testRuntimeOnly("org.junit.platform:junit-platform-launcher")
}

tasks.test {
    useJUnitPlatform()
}
```

- The Spring Boot **plugin** adds `bootRun` (run the app) and `bootJar` (build one runnable jar). The dependency-management plugin applies Spring Boot's BOM, so the starters need no versions (<Ref to="java-build-testing" />).
- **Starters** are dependency bundles: `spring-boot-starter-webmvc` brings Spring MVC, Tomcat and Jackson; `spring-boot-starter-validation` brings Bean Validation.
- The **toolchain** asks Gradle for a JDK 21 to compile with, whatever JDK runs Gradle itself.

The application's entry point is a class marked **`@SpringBootApplication`**, in `src/main/java/com/bakery/BakeryApplication.java`:

```java
package com.bakery;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class BakeryApplication {
    public static void main(String[] args) {
        SpringApplication.run(BakeryApplication.class, args);
    }
}
```

`@SpringBootApplication` turns on auto-configuration and **component scanning**: Spring finds every class marked `@RestController`, `@Service`, `@Component` and so on in this package and below, creates one instance of each, and wires them together. Run the app with `./gradlew bootRun`; it listens on port 8080.

## Controllers and routes

A **controller** is a class whose methods handle requests. Put this in `MenuController.java`:

```java
package com.bakery;

import java.util.Comparator;
import java.util.List;
import java.util.Map;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/products")
public class MenuController {
    public record Product(String sku, String name, int pricePence, String category) {}

    private final Map<String, Product> products = Map.of(
        "RYE-400", new Product("RYE-400", "Rye loaf", 450, "bread"),
        "BAG-250", new Product("BAG-250", "Bagel", 120, "bread"),
        "CRO-090", new Product("CRO-090", "Croissant", 275, "pastry"));

    @GetMapping
    List<Product> list(@RequestParam(required = false) String category,
                       @RequestParam(defaultValue = "1") int page,
                       @RequestParam(defaultValue = "2") int size) {
        int pageSize = Math.clamp(size, 1, 50);
        return products.values().stream()
            .filter(p -> category == null || p.category().equals(category))
            .sorted(Comparator.comparing(Product::sku))
            .skip((long) (Math.max(page, 1) - 1) * pageSize)
            .limit(pageSize)
            .toList();
    }

    @GetMapping("/{sku}")
    ResponseEntity<Product> get(@PathVariable String sku) {
        Product product = products.get(sku);
        return product == null ? ResponseEntity.notFound().build() : ResponseEntity.ok(product);
    }
}
```

- **`@RestController`** marks a controller whose return values are written as JSON (with Jackson); `@RequestMapping("/products")` sets a prefix for every route in the class.
- **`@GetMapping`**, `@PostMapping`, `@PutMapping`, `@DeleteMapping` map methods to routes.
- **`@PathVariable`** binds a part of the path; **`@RequestParam`** binds the query string, with `required = false` or a `defaultValue` for optional ones.
- **`ResponseEntity`** lets you choose the status and headers; returning a plain object means 200.

## Request bodies, validation and services

**`@RequestBody`** binds the JSON body to a record, and **`@Valid`** checks its **Bean Validation** annotations (`@NotBlank`, `@Size`, `@Min`, `@Max`, `@Pattern`, `@Email` and more) before the method runs. The work itself belongs in a **service**, which Spring passes to the controller's constructor. Here is the service, `OrderService.java`:

```java
package com.bakery;

import java.util.List;
import java.util.Map;
import java.util.Optional;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicInteger;
import org.springframework.stereotype.Service;

@Service
public class OrderService {
    public record Line(String sku, int quantity) {}
    public record Order(String id, String customer, List<Line> lines, String status) {}

    private final Map<String, Order> orders = new ConcurrentHashMap<>();
    private final AtomicInteger next = new AtomicInteger(1000);

    public Order place(String customer, List<Line> lines) {
        var order = new Order("o-" + next.incrementAndGet(), customer, List.copyOf(lines), "placed");
        orders.put(order.id(), order);
        return order;
    }

    public Optional<Order> find(String id) {
        return Optional.ofNullable(orders.get(id));
    }

    public Order cancel(String id) {
        Order order = find(id).orElseThrow(() -> new OrderNotFoundException(id));
        if (order.status().equals("shipped")) throw new OrderAlreadyShippedException(id);
        Order cancelled = new Order(id, order.customer(), order.lines(), "cancelled");
        orders.put(id, cancelled);
        return cancelled;
    }
}
```

and the controller, `OrderController.java`:

```java
package com.bakery;

import jakarta.validation.Valid;
import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Pattern;
import jakarta.validation.constraints.Size;
import java.net.URI;
import java.util.List;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/orders")
public class OrderController {
    public record LineRequest(
        @NotBlank @Pattern(regexp = "^[A-Z]{3,4}-[0-9]{2,4}$") String sku,
        @Min(1) @Max(99) int quantity) {}

    public record PlaceOrderRequest(
        @NotBlank @Size(max = 100) String customer,
        @Size(min = 1, max = 50) List<@Valid LineRequest> lines) {}

    private final OrderService orders;

    public OrderController(OrderService orders) {
        this.orders = orders;
    }

    @PostMapping
    ResponseEntity<OrderService.Order> place(@Valid @RequestBody PlaceOrderRequest request) {
        var lines = request.lines().stream().map(l -> new OrderService.Line(l.sku(), l.quantity())).toList();
        var order = orders.place(request.customer(), lines);
        return ResponseEntity.created(URI.create("/orders/" + order.id())).body(order);
    }

    @GetMapping("/{id}")
    ResponseEntity<OrderService.Order> get(@PathVariable String id) {
        return ResponseEntity.of(orders.find(id));
    }

    @PostMapping("/{id}/cancel")
    OrderService.Order cancel(@PathVariable String id) {
        return orders.cancel(id);
    }
}
```

Notes:

- The controller's **constructor** asks for an `OrderService`, and Spring supplies the single instance it created: **constructor injection**, the recommended style. The service is a singleton shared by every request at once, so it uses `ConcurrentHashMap` and `AtomicInteger` (<Ref to="java-errors-concurrency" />).
- **`ResponseEntity.created(uri)`** gives 201 with a `Location` header; **`ResponseEntity.of(optional)`** gives 200 with the value or 404 when empty.
- `List<@Valid LineRequest>` validates each line too. Validation annotations come from the `jakarta.validation` package (Jakarta EE is the successor of Java EE).
- Request and response records are separate from the stored data, so clients cannot set fields such as `status` (**over-posting**, <Ref to="m-appsec" />).

## Errors as problem details

Spring Boot can send every error as RFC 9457 problem details. Turn it on in `src/main/resources/application.properties`, which is also where other settings go:

```properties
spring.application.name=bakery-api
spring.mvc.problemdetails.enabled=true
server.error.include-stacktrace=never
server.error.include-message=never
```

Then map your own exceptions to statuses in one place with a **`@RestControllerAdvice`**, `ApiErrors.java`:

```java
package com.bakery;

import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

class OrderNotFoundException extends RuntimeException {
    OrderNotFoundException(String id) {
        super("No order " + id);
    }
}

class OrderAlreadyShippedException extends RuntimeException {
    OrderAlreadyShippedException(String id) {
        super("Order " + id + " left the bakery and can no longer be cancelled.");
    }
}

@RestControllerAdvice
class ApiErrors {
    @ExceptionHandler(OrderNotFoundException.class)
    ProblemDetail notFound(OrderNotFoundException e) {
        return ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, e.getMessage());
    }

    @ExceptionHandler(OrderAlreadyShippedException.class)
    ProblemDetail shipped(OrderAlreadyShippedException e) {
        ProblemDetail problem = ProblemDetail.forStatusAndDetail(HttpStatus.CONFLICT, e.getMessage());
        problem.setTitle("Order already shipped");
        return problem;
    }
}
```

Exceptions you do not map become a generic 500, logged on the server with no details sent to the client; validation failures become 400s. In Spring it is normal to signal expected failures with exceptions mapped like this, unlike in ASP.NET Core where returning results is more common.

## Trying it

Run `./gradlew bootRun`, and in another terminal call the API with `curl`. `-s` hides progress, `-w` prints the status after the body:

```bash
curl -s "localhost:8080/products?category=pastry"; echo
curl -s -o /dev/null -w "%{http_code}\n" localhost:8080/products/NOPE
curl -s -i -X POST localhost:8080/orders -H "Content-Type: application/json" \
  -d '{"customer":"Ama","lines":[{"sku":"RYE-400","quantity":2}]}' | grep -E "^HTTP|^Location"
curl -s -X POST localhost:8080/orders -H "Content-Type: application/json" \

curl -s -X POST localhost:8080/orders/o-404/cancel; echo
curl -s localhost:8080/v3/api-docs | grep -o '"/orders/{id}/cancel"'
```

## Configuration and profiles

Settings live in `application.properties` (or `application.yaml`). Read them with **`@Value("${bakery.free-delivery-from-pence}")`**, or better, bind a group of them to a record with **`@ConfigurationProperties`** (<Ref to="be-dependency-injection" />). **Profiles** select extra settings files for an environment: with `SPRING_PROFILES_ACTIVE=prod`, `application-prod.properties` is read too. Environment variables override files, with dots replaced by underscores and upper case: `SERVER_PORT=9090`, `BAKERY_FREEDELIVERYFROMPENCE=3000`. Keep secrets out of the properties files; use environment variables or a secret store (<Ref to="m-appsec" />).

## Spring Web MVC and WebFlux

This chapter uses **Spring MVC**, where each request runs on its own thread. With virtual threads (`spring.threads.virtual.enabled=true`) that model handles very high concurrency (<Ref to="java-errors-concurrency" />). You will also meet **Spring WebFlux**, a reactive alternative built on `Mono` and `Flux` types. It is harder to write and debug; most new services use MVC, now with virtual threads.

## Common mistakes

- **Field injection** (`@Autowired` on fields) instead of constructor injection, which hides dependencies and complicates tests.
- **Forgetting `@Valid`**, so the validation annotations are silently ignored.
- **Returning JPA entities** directly from controllers (over-posting, and lazy-loading surprises, <Ref to="be-data-jpa" />).
- **Catching exceptions in every controller method** instead of one `@RestControllerAdvice`.
- **Mutable state in singleton services** without thread safety.
- **Stack traces in error responses**, or secrets in `application.properties` committed to Git.

## Practice

**1. (warm-up)** In `@GetMapping("/shops/{city}/products") List<Product> list(@PathVariable String city, @RequestParam(required = false) String q, @RequestParam(defaultValue = "1") int page)`, called as `/shops/leeds/products?q=rye`, what are `city`, `q` and `page`?

<Solution>

`city` is `leeds` (from the path), `q` is `rye` (from the query string), and `page` is `1`, its default, because the query string does not include it.

</Solution>

**2. (warm-up)** Why does Spring recommend constructor injection over `@Autowired` fields?

<Solution>

The constructor lists every dependency, so they are obvious and can be `final`; the object can never exist half set up; and a test can create it with `new OrderController(fakeService)` without Spring at all. Field injection hides dependencies and needs Spring or reflection to fill them.

</Solution>

**3. (standard)** Add `DELETE /stock/{sku}` to a new controller that keeps stock items in a `ConcurrentHashMap`: 204 when removed, 404 when it did not exist.

<Solution>

```java
package com.bakery;

import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class StockController {
    private final Map<String, String> stock = new ConcurrentHashMap<>(Map.of("JAM-380", "Jam"));

    @DeleteMapping("/stock/{sku}")
    ResponseEntity<Void> delete(@PathVariable String sku) {
        return stock.remove(sku) != null ? ResponseEntity.noContent().build() : ResponseEntity.notFound().build();
    }
}
```

Calling `DELETE /stock/JAM-380` twice gives **204** and then **404**.

</Solution>

**4. (standard)** A colleague's controller method catches every exception and returns `ResponseEntity.status(500).body(e.getMessage())`. What is wrong, and what should they do?

<Solution>

It sends internal error messages to clients (which can leak details such as SQL, host names or secrets), returns 500 even for the client's mistakes, and repeats error handling in every method. Instead, let exceptions propagate; map expected ones (not found, conflict, validation) to the right status with `ProblemDetail` in one `@RestControllerAdvice`; let unexpected ones become Spring's generic 500, which is logged with the full stack trace on the server only.

</Solution>

## Summary

- **Spring Boot** auto-configures Spring from the **starters** you add and runs as one jar with an embedded server; start projects at Spring Initializr and run them with `./gradlew bootRun`.
- **`@RestController`** classes map routes with `@GetMapping` and friends; `@PathVariable`, `@RequestParam` and `@RequestBody` bind request data; `ResponseEntity` sets status and headers.
- **`@Valid`** with Bean Validation annotations checks request records before your code runs.
- **Services** (`@Service`) hold the logic and are injected through constructors.
- **Problem details** with `spring.mvc.problemdetails.enabled=true` and a **`@RestControllerAdvice`** mapping exceptions to `ProblemDetail`.
- **springdoc** generates the **OpenAPI** document at `/v3/api-docs`. Configure with properties files, **profiles** and environment variables.
