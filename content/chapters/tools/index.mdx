## The loop

1. You describe the available tools: name, purpose, and input schema.
2. The model either answers, or replies with a request to call a tool with specific arguments.
3. Your code runs the tool. The model never executes anything itself.
4. You send the result back, and the model continues.

```python
# Uses client, MODEL and reply_text from "Your first model call".
tools = [{
    "name": "get_order_status",
    "description": "Look up the current status of a customer order by its ID.",
    "input_schema": {
        "type": "object",
        "properties": {"order_id": {"type": "string"}},
        "required": ["order_id"],
    },
}]

def get_order_status(order_id: str) -> str:
    return {"A17": "shipped", "B42": "processing"}.get(order_id, "not found")

messages = [{"role": "user", "content": "Where is order B42?"}]
while True:
    msg = client.messages.create(model=MODEL, max_tokens=1000,
                                 tools=tools, messages=messages)
    messages.append({"role": "assistant", "content": msg.content})
    if msg.stop_reason != "tool_use":
        break
    results = []
    for block in msg.content:
        if block.type == "tool_use":
            out = get_order_status(**block.input)
            results.append({"type": "tool_result",
                            "tool_use_id": block.id, "content": out})
    messages.append({"role": "user", "content": results})

print(reply_text(msg))
```

## Designing good tools

- The description is a prompt. Say what the tool does, when to use it, and what it returns.
- Few, clear tools beat many overlapping ones.
- Return errors as readable text so the model can recover.
- Validate arguments. The model can invent an ID or pass a bad value.
- Anything destructive or costly (sending email, paying, deleting) should require confirmation from a person.
